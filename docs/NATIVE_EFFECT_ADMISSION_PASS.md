## Probe 1 — targeted rotate/zoom

### What it contains

One four-second `clip-a.mov` on the spine, one `adjust-transform`, nothing else.

Targeting is done by **position compensation**, not by moving the anchor:
`SpatialTransformMath.targetedCompensation` solves for the translation that
places the chosen point at centre after scale and rotation. That keeps every
construction inside observed territory — animated position, scale, and rotation
are all captured; an animated anchor is not.

Source point `(0.7, 0.35)`, scale 1 → 1.5, rotation 0° → 12° over 120 frames.

### Predicted return

| Element | Predicted |
| --- | --- |
| `position` X keyframes | `0` at `0s`, **`-60.48434`** at `4s` |
| `position` Y keyframes | `0` at `0s`, **`-15.77097`** at `4s` |
| `scale` keyframes | `1 1` at `0s`, `1.5 1.5` at `4s` |
| `rotation` keyframes | `0` at `0s`, `12` at `4s` |
| keyframe origin | `0s`, **never `3600s`** |
| `rotation` param | no `key` attribute |
| spine `asset-clip` count | 1 |

The two compensation values were computed by hand and match the emitter to five
decimals. Their **signs** are the interesting part: the target is right of and
above centre, so the framing must move left (X negative) and down (Y negative,
because Final Cut's +Y is up).

### Reading the result

| Returned state | Meaning |
| --- | --- |
| all four params intact at the predicted values | **admitted** |
| `rotation` param missing or emptied | rotation is not admitted from a generated file |
| `rotation` gains a `key` attribute | Final Cut normalised it; the capture's bare form is not required |
| position flattened to a `position="x y"` attribute | Final Cut collapsed an animation it considered static — inspect the keyframe times |
| keyframe times rewritten to a `3600s` base | the origin is not a property of the media kind after all |
| Y sign inverted | the axis convention is wrong, and every vertical pan the emitter produces is backwards |
| values rounded or altered | the emitter's precision does not survive |

## Probe 2 — old television

### What it contains

One four-second `clip-a.mov` on the spine carrying:

- an **animated** `adjust-blend` flicker (1 → 0.82 → 1 over the first second)
- a **connected** `living-still.png` overlay at `lane="1"`, `offset="1s"`,
  2 s long, with a **static** `adjust-blend amount="0.5" mode="14 (Overlay)"`
- a Color Adjustments `filter-video` with Saturation 25

### The one thing under test

**Only the connected layer is unobserved.** The animated `adjust-blend`, the
Color Adjustments filter, and the movie asset/`asset-clip` construction have all
returned intact from earlier passes. That is deliberate: a failure has one
candidate cause.

### Predicted return

| Element | Predicted |
| --- | --- |
| `<video>` position | a **child** of the spine `asset-clip`, not a sibling |
| `lane` | `1` |
| `offset` | **`1s`** — parent-relative; the parent starts at `0s` so this is the degenerate case |
| overlay `start` | `3600s` — a still keeps its origin even inside a movie clip |
| overlay blend | `amount="0.5" mode="14 (Overlay)"`, attributes not params |
| spine `adjust-blend` | animated param form, three keyframes, unchanged |
| child order | `adjust-blend`, then `<video>`, then `<filter-video>` |
| `enabled="0"` anywhere | absent |

### Reading the result

| Returned state | Meaning |
| --- | --- |
| everything above intact | **admitted** |
| overlay hoisted to a sibling or its own spine | our document shape is wrong even though it validates |
| `lane` renumbered | lane numbering is not ours to choose |
| `offset` rewritten | the parent-relative reading is wrong — re-read `docs/CONNECTED_LAYERS_GROUND_TRUTH.md` §6 |
| `mode` emptied or changed | `"14 (Overlay)"` is not accepted on the way *in*, only written on the way out |
| overlay dropped entirely | connected layers are not admitted from a generated file |
| overlay `start` rewritten to `0s` | the still origin does not apply in this context |

## Steps

Run both in one session. Stop at the first failure and record it.

1. `pgrep -lf "Final Cut"` prints nothing.
2. `Scripts/launch-isolated-fcpcommandconsole --launch`
3. Open `/Users/marcboyer/Movies/FCPCommandConsole/FCPCommandConsole Test.fcpbundle`
   (absolute path — `~` resolves inside the sandbox HOME).
4. File ▸ Import ▸ XML…, choose the rotate/zoom probe's `.fcpxml`.
5. **If Final Cut crashes or errors, stop** and record the message.
6. Play it once. Expect a slow zoom toward a point up and to the right, with a
   slight clockwise rotation.
7. Do **not** edit anything.
8. Select the project in the browser, File ▸ Export XML…, name it `returned`,
   save into that package's `Returned/` directory.
9. Repeat 4–8 for the old television probe. Expect a faint flicker in the first
   second, a desaturated image, and a translucent still appearing over it from
   1 s to 3 s.

## What a pass would admit

Admission of these two generated constructions, and nothing more.

It would **not** admit editability — a separate pass, and the dissolve work
showed why the two are distinct. It would not admit the compositions' own
numbers: the rotate/zoom probe's target point and the old television probe's
saturation and flicker floor are all chosen, not derived from any observed
mapping between creative language and parameter values.

A pass on both would complete the contract set for all four Phase 1 workflows.
Admitting them into `service/FinalCutSemanticProfile.swift` is a **separate,
deliberate edit** — observing a semantic and admitting its contract remain
separate acts.
